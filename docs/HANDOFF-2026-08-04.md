## 1. What shipped today, both commits local-only

### Piece 3 of listing encoding v2 — `dd0f565`

The 3-step encoding flow redesign from `docs/BRIEF-listing-encoding-v2.md` §2/§8b:

- `ListingForm.tsx`'s fixed 5-option `category` `<select>` is gone, replaced by a chip picker
  (icon + name) sourced from `property_types` — **active rows with a `legacy_category` mapping
  only**. A type added through the Settings screen has no legacy mapping, and `listings.category`
  stays `NOT NULL` until apply 3, so picking one would throw a raw DB exception
  (`sync_listing_property_type()`'s `legacy_category_of` guard) — excluding it from the pick list
  is what keeps that unreachable rather than surfacing as an ugly error.
- New `Frontage` field (free text, unvalidated, per the brief). `area_detail` relabelled
  "Property location" — no schema change, UI text only.
- Status/publishing moved OFF the three encoding steps entirely, into the sticky action bar's
  **"Status ▾" dropdown**. The primary move (whichever of submit/publish/relist applies) stays a
  direct bar button; everything else (send-back, sell, withdraw) lives behind the menu.
  `LifecyclePanel` itself is unchanged beyond the shorter `transitions` list it's now given.
- **Two pre-existing bugs found and fixed in `ListingActionBar.tsx`**, both blocking this piece's
  own E2E verification, neither introduced by it:
  - `confirming` was a plain boolean with no reset, so a stale "Yes — …" prompt from one primary
    transition could bleed into the next one's render without ever being clicked.
  - `LifecyclePanel`'s empty-state copy was hardcoded to "This listing is sold", reachable now for
    any status once its secondary move list drains to empty, not just a real sale.
- Sample (chip style vs. plain dropdown; Status-in-top-bar vs. Status-as-a-visible-section) was
  built as a real HTML mockup and approved in chat before any code was written, including after
  being told the dropdown choice would cost a ~12-point rewrite of the E2E suite — it did, and that
  rewrite is part of this commit.

### Heading-role fix — `53de410`

The listing title in the action bar was a plain `.ttl` div — the only place the title appears as
text on `/admin/listings/[id]`, with no heading role, so a screen-reader user tabbing by headings
had nothing to land on. Now `<h1 className="ttl">`; verified the existing `.aabar .ttl` CSS rule
outranks the generic `h1,h2,h3` one on every property they share, and the sheet's global
`*{margin:0}` reset already strips h1's default margin, so nothing moved visually. Found while
building piece 3, flagged as a separate task, fixed same session once the user picked it up.

## 5. Traps that cost time this session, still true

- **The two-root path trap.** Prefix repo paths with `dascout/` from the workspace root.
- **A DOM-restructuring UI change is not "just" a visual change if a real E2E suite clicks the
  restructured elements.** Moving Status/Publish into a dropdown looked like a pure layout call
  from the sample alone; it actually required rewriting ~12 interaction points across a 24-step
  serial Playwright suite (primary vs. secondary transition routing, menu-open steps, a stale
  confirm-state bug it exposed). Surface that cost to the owner before committing to the direction,
  not after — this session did, and got an explicit "proceed anyway."
- **Playwright's `webServer` won't reuse a manually-started `npm run start`** —
  `reuseExistingServer: false` in `playwright.config.ts` is deliberate; kill anything on :3000
  yourself before running `npx playwright test`, don't start the server by hand first.
- **Transient E2E failures happen in this environment** — a synthetic large-photo downscale and a
  live-listing price edit (which triggers 3 extra `revalidatePath` calls) each timed out once and
  passed clean on retry. Retry once before treating a failure as a real regression; don't retry
  more than that without reading the actual error context.
- **`property_types.icon` is a closed sprite-symbol set** (`components/IconSprite.tsx`) — verified
  `pin`/`tag`/`area`/`home`/`key` all exist before using them in the piece 3 chip picker; check
  before adding any new icon name anywhere.
- **`web/AGENTS.md` is real.** Next.js **16.2.12**, not the Next in your training data.
- **Never run `npm audit fix --force`** — it downgrades Next to 9.3.3.
