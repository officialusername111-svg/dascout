## Known, accepted, and needing a decision

**The E2E suite writes to the production database.** Every full `npx playwright test` run leaves
roughly 10 `zz-*` test listings in the live Supabase project. They had accumulated to 101 before
the 2026-08-01 cleanup, and the suite recreated 10 more the same evening.

- **Not a public problem** — only `live` listings render, and test rows are never `live`. It is
  admin-panel clutter.
- **But the cleanup is not durable.** "Delete the test listings" recurs after every test run.
- **Durable fix needs the owner's call:** a separate Supabase project, a Supabase branch, or a
  global-teardown in the suite. The fixtures already self-identify with a `zz-` slug prefix, so
  teardown would be straightforward.

Cleanup recipe (`verification_events` is the only `RESTRICT` FK on listings; the other six CASCADE,
so its rows go first):

```sql
with doomed as (select id from public.listings where status <> 'live')
delete from public.verification_events where listing_id in (select id from doomed);
delete from public.listings where status <> 'live';
```

## Things that will bite you if you don't know them

- **`web/AGENTS.md` is real:** this is Next.js **16.2.12** and it is not the Next.js in your
  training data. Read `web/node_modules/next/dist/docs/` before using any Next API, and follow the
  patterns already in the repo rather than inventing new ones.
- **No peso amounts and no map anywhere public** — a standing rule, enforced at the data layer
  (public queries never select `price_php`). Two E2E specs assert it. Never reintroduce either.
- **The site header is white by design** (`header{background:#fff}`). The dark header in the v6
  mockup was a mockup simplification. Do not "fix" it to black.
- **Four deliberate deviations from the v6 mockup** are reasoned in
  `docs/agent-runs/run-v6-home-black.md`. Do not treat them as drift and revert them.
- **The token trap:** run `run-p5b-double-optin` used a row's own UUID as an email token. That was
  acceptable there because the blast radius was only "alerts to an address you already controlled".
  **It does not transfer to admin invites.**
- **Commits go straight to `main`** — no PR ceremony, per the owner's convention.
- **Never run `npm audit fix --force`** — it downgrades Next to 9.3.3.
